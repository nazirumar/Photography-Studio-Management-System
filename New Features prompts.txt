# 1. REQUIRED TECHNOLOGY STACK

Use this architecture unless repository inspection reveals a compatibility issue.

| Layer                          | Technology                               | Purpose                        |
| ------------------------------ | ---------------------------------------- | ------------------------------ |
| Main application               | Django                                   | Existing StudioFlow            |
| Main database                  | PostgreSQL                               | Authoritative business data    |
| Agent orchestration            | LangGraph                                | Stateful FDE workflows         |
| Primary AI                     | OpenAI                                   | Reasoning and generation       |
| Structured output              | Pydantic                                 | Validated AI/tool schemas      |
| Embeddings                     | OpenAI embeddings                        | Knowledge embeddings           |
| Vector search                  | PostgreSQL + pgvector                    | Private StudioFlow knowledge   |
| Optional future vector service | Pinecone                                 | Large-scale future RAG         |
| Background jobs                | Celery                                   | Async processing               |
| Scheduler                      | Celery Beat                              | Scheduled AI operations        |
| Cache / queue                  | Redis                                    | Celery, caching, rate limiting |
| Agent persistence              | PostgreSQL                               | LangGraph checkpoints/state    |
| AI observability               | LangSmith + application logging          | Agent tracing/evaluation       |
| Audit                          | PostgreSQL                               | FDE decision/action history    |
| External research              | Tavily or approved search provider       | Explicit external research     |
| Storage                        | Existing S3-compatible storage           | Documents/files                |
| Deployment                     | Docker                                   | Reproducible deployment        |
| Reverse proxy                  | Existing production infrastructure/Nginx | HTTP serving                   |

Do NOT add Pinecone initially unless benchmarking demonstrates that pgvector is insufficient.

# 2. CORE ARCHITECTURAL PRINCIPLE

The system must follow:

```text
LLM        = reasoning
LangGraph  = orchestration
Django     = business rules/actions
PostgreSQL = source of truth
pgvector   = unstructured knowledge
Redis      = cache/queue
Celery     = asynchronous work
Human      = approval authority
```

The LLM must NOT become the source of truth.

# NON-NEGOTIABLE RULE

Always preserve this separation:

```text
AI thinks.
LangGraph coordinates.
Django validates and acts.
PostgreSQL stores truth.
pgvector retrieves knowledge.
Celery performs background work.
Humans approve consequential actions.
```

Build the FDE as a secure operational intelligence layer on top of StudioFlow, not as a chatbot with direct database access.
